# Study Planner

HTML, CSS, JavaScript 프런트엔드와 Node.js/Express 서버로 구성된 학습 일정 관리 앱입니다.

## 실행

Node.js 18 이상에서 실행합니다.

```sh
npm install
npm start
```

브라우저에서 http://127.0.0.1:3000 을 엽니다. HTML 파일을 직접 열지 말고 서버 주소로 접속하세요.
포트는 `PORT` 환경 변수로 변경할 수 있습니다.

## 저장 방식

- 페이지를 열 때 `GET /api/schedules`로 일정과 과목별 색상을 불러옵니다.
- 등록은 `POST /api/schedules`, 수정과 완료 상태 변경은 `PATCH /api/schedules/:id`, 삭제는 `DELETE /api/schedules/:id`로 저장합니다.
- 과목별 색상은 `PATCH /api/courses/:subject/color`로 저장하며, 해당 과목의 모든 일정에 적용합니다.
- 로컬에서는 `data/study-planner.json`, PostgreSQL 연결 환경에서는 데이터베이스에 기록한 후 응답합니다. 파일 저장은 순차 처리하고, PostgreSQL 저장은 트랜잭션과 행 잠금으로 여러 서버 인스턴스의 동시 변경을 보호합니다.
- localStorage는 기존 일정의 일회성 서버 이전에만 사용합니다. 서버 저장에 성공한 이후 이전 데이터를 제거합니다.
- 저장 요청이 실패하면 화면에 오류를 표시하고, 마지막으로 서버에서 확인한 상태를 유지합니다. 처음 연결에 실패한 경우 ‘서버 확인’ 버튼으로 다시 불러올 수 있습니다.

서버를 재시작해도 데이터 파일은 유지됩니다. 백업할 때는 `data` 디렉터리를 보관하세요. `STUDY_PLANNER_DATA_DIR` 환경 변수로 저장 경로를 변경할 수 있으며, 배포 환경에서는 이 경로에 영구 볼륨을 연결해야 합니다. 동일한 데이터 파일은 한 서버 프로세스에서 사용하세요.

현재 모든 접속자는 같은 일정 데이터를 사용합니다.

## Vercel 배포

Vercel 함수의 파일 시스템은 영구 저장소가 아니므로 로컬 JSON 파일을 사용할 수 없습니다.

1. Vercel 프로젝트에서 **Storage / Marketplace**의 PostgreSQL 제공자(예: Neon)를 연결합니다.
2. 프로젝트 **Settings → Environment Variables**에서 `DATABASE_URL` 또는 `POSTGRES_URL`이 Production 환경에 설정되어 있는지 확인합니다. 제공자가 제공하는 연결 URL을 그대로 사용하세요. 연결 문자열은 GitHub에 올리거나 프런트엔드 코드에 넣지 않습니다.
3. 환경 변수 설정 후 **Redeploy**합니다. 테이블(`study_planner_state`)은 첫 API 요청에서 자동으로 생성됩니다. 연결 계정에는 테이블 생성 및 읽기·쓰기 권한이 필요합니다.
4. `/api/health`에서 정상 응답을 확인한 뒤 일정 등록·완료·색상 변경 후 새로고침해 유지되는지 확인합니다.

Vercel에서는 Express 앱을 내보내며, 요청 전에는 저장소를 초기화하지 않습니다. 데이터베이스가 연결되지 않아도 화면은 열리고, API는 설정 안내를 담은 HTTP 503을 반환합니다. 임시 파일이나 메모리 저장으로 성공을 가장하지 않습니다.

로컬 JSON 데이터는 외부 데이터베이스로 자동 복사되지 않습니다. 기존 데이터가 있는 경우 전환 전에 JSON 파일을 백업하세요. 데이터베이스 연결 없이 로컬에서 실행하면 기존 JSON 데이터를 계속 사용합니다.

## 검증

```sh
npm test
```

테스트는 임시 저장 디렉터리와 별도 포트를 사용하므로 실제 일정 데이터에 영향을 주지 않습니다. 일정 CRUD, 동시 수정, 완료 상태, 색상 유지, 입력 검증, 서버 재시작 및 기존 데이터 이전을 검증합니다. Vercel 환경의 앱 로딩·정적 파일·DB 미설정 응답과 PostgreSQL 트랜잭션 호출도 검증합니다. PostgreSQL 테스트는 대역을 사용하며 실제 배포 DB 접속 검증은 별도로 필요합니다.
